# Foundation architecture

- **Core**: explicit state commands, independent pause leases, immutable normalized
  input command, release-to-rearm input gate. Pure C#, no UnityEngine references.
- **Platform**: clone/own InputActionAsset; read per rendered frame; clear command
  on lost focus/device removal; refuse held input until neutral after resume.
  Lifecycle adapter tracks focus and OS pause separately and requires confirmation.
- **Presentation**: safe-area uGUI title shell, local text keys, overlay ownership.
  No wallet, save mutation, networking or vehicle simulation in views.
- **Composition**: persistent AppRoot created only by Bootstrap. Owns dependencies,
  physics timestep/timeScale policy, scene load and subscriptions. Title can be
  opened directly in Editor; it redirects through Bootstrap for the same flow.
- **Editor**: explicit project preparation/validation and native smoke-build entry
  points. Build validator rejects a mismatched editor, missing setup and wrong scenes.
- **Tests**: EditMode pure contracts + project setup, PlayMode boot/title/input tests.

## Flow implemented at M0
`Bootstrap -> BootCompleted -> Title`; About and Controls panels acquire leases.
Application interruption records previous state, acquires a separate lease, clears
input, and exposes a confirm-to-resume panel only once focused and not OS-paused.
Dismissing one panel never releases another owner's pause. AppRoot alone sets
Time.timeScale. UI uses unscaled event dispatch; no fuel or wall-clock simulation.

The remaining state vocabulary is declared for future milestones. State transition
tests are contract tests, not claims that a Garage or Driving scene exists.
Title provides no fake expedition, rewards, save-success message or network login.

## Future dependencies (do not implement ahead of gates)
M1 vehicle command consumer/parking hold -> M2 immutable campaign snapshots and
transaction service -> save acknowledgment -> bank/quest/UI events -> M3 region
leases and local Addressables -> data-driven M4 campaign. Inputs never write saves.
